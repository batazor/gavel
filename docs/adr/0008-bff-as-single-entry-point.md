# 8. BFF as the single public entry point

Date: 2026-10-21

## Status

Accepted. Уточняет ADR-0006: публичный SSE-endpoint живёт в BFF, а не в auction-service.

## Context

С ростом числа контекстов (ADR-0004) браузер вынужден знать о каждом сервисе, ingress — держать маршрут на каждый, а SSE-соединения — жить в доменных сервисах. Страницы аукциона собираются из нескольких контекстов (лот из Catalog, цена и ставки из Auction).

Варианты:
1. **Astro SSR как BFF.** Node-процесс Astro ходит в сервисы и отдаёт HTML. Но тогда Node держит SSE-соединения и становится вторым языком бэкенда.
2. **Отдельный Rust BFF.** Единственный сервис, открытый наружу. Astro рендерит и ходит только в BFF.

## Decision

Вариант 2. **BFF — Rust-сервис, единственная публичная точка входа.**

- Ingress маршрутизирует только на `web` (HTML) и `bff` (API + SSE). Доменные сервисы наружу не видны, между ними только mTLS меша.
- BFF **компонует** ответы для экранов (лот + текущая цена + история), **переводит** команды в вызовы доменных сервисов и **фан-аутит** события в SSE. Доменных правил в BFF нет: если правило появилось в BFF, оно переезжает в контекст.
- **SSE fan-out** в BFF подписан на брокер (`BidPlaced`, `AuctionClosed`). При переподключении с `Last-Event-ID` BFF дозапрашивает пропущенные события у auction-service по версии потока. Публичный SSE-endpoint auction-service не нужен.
- JWT по-прежнему проверяет ingress (ADR-0002), BFF доверяет заголовкам от меша и пробрасывает `user_id` дальше.

## Consequences

- Ещё один сервис и ещё один hop. Плата за одну поверхность API и за централизованные долгоживущие соединения.
- Брокер попадает на горячий путь realtime. Выбор брокера (отдельный ADR) должен учитывать задержку доставки.
- Keploy записывает трафик на границе BFF, это естественная точка для контрактных тестов.
- Для второго клиента (мобильный, админка) заводится свой BFF, общий не растим.
