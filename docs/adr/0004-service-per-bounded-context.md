# 4. Service per bounded context, database per service

Date: 2026-10-21

## Status

Accepted

## Context

Нужно решить, монолит с модулями или сервисы. Проект обкатывает cloud native, Istio и OTLP-трассировку между сервисами. На монолите эти практики почти не проявляются.

## Decision

Микросервисы. Один bounded context = один Rust-сервис со своей базой данных. Никто, кроме владельца, в чужую базу не ходит. Стартовые контексты: Auction (торги) и Catalog (лоты).

Внутри сервиса — hexagonal: HTTP-адаптер → агрегат → репозиторий → БД. Домен не зависит от инфраструктуры.

## Consequences

- Нет транзакций между контекстами. Интеграция Catalog → Auction (LotListed) идёт через события или вызов, решение отдельным ADR.
- Больше инфраструктуры с первого дня: по поду на сервис и на базу, меш между ними. Это осознанная цена, ради неё проект и затеян.
- Lean-доказательства остаются внутри контекста Auction и не зависят от сетевых границ.
- На диаграммах БД рисуется внутри контекста и внизу: поток сверху вниз, хранилище — конечная точка.
