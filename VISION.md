# Gavel — цели проекта

Учебно-исследовательский проект: аукцион, на котором обкатываем современный стек и практики.
Документ фиксирует, *что* хотим сделать. Детали каждого пункта — в ADR / спеках по мере принятия решений.

## Что строим

1. **Аукцион.** Лоты, ставки, завершение торгов, определение победителя.
   Тип аукциона (английский / голландский / закрытые ставки / Vickrey) — решить первым, он определяет доменную модель.

## Как строим

2. **SDD — Spec-Driven Development.** Сначала спецификация (требования, сценарии, инварианты), потом код. Спеки живут в репозитории рядом с кодом и являются источником правды для тестов и доказательств.
3. **Метрики и трассировка через OTLP.** Полная интеграция OpenTelemetry: traces, metrics, logs. Экспорт по OTLP в коллектор, дальше Grafana-стек (Tempo / Mimir / Loki).
4. **Формальные доказательства в Lean.** Ключевые инварианты аукциона (например: победитель всегда платит не больше своей ставки; ставка ниже текущей не принимается; аукцион завершается ровно один раз) доказываются в Lean 4. Спека (п. 2) — источник утверждений для доказательств.
5. **DDD + микросервисы.** Один bounded context = один сервис + своя БД (ADR-0004). Агрегаты, доменные события, ubiquitous language. Домен не зависит от инфраструктуры.
6. **Rust** — бэкенд.
7. **Keploy** — попробовать для записи/воспроизведения интеграционных тестов. Эксперимент: проверить, заходит ли, и зафиксировать вывод.
8. **Аутентификация: OAuth + JWT.** Внешний провайдер, из токена берём `user_id` (sub). Своей базы пользователей не держим, этого должно хватить.
9. **Astro** — фронт.
10. **Cloud native.** Контейнеры, Kubernetes, конфигурация через окружение, health/readiness, graceful shutdown, 12-factor.
11. **Service mesh (Istio).** Rate limiting, mTLS, retries/timeouts и трассировка на уровне меша, а не в коде приложения. Приложение не знает о лимитах.
12. **ADR** (Architecture Decision Records). Каждое архитектурное решение фиксируется в `docs/adr/`. Открытые вопросы ниже закрываются через ADR.
13. **Архитектура как код: LikeC4.** Модель в `architecture/`, диаграммы генерируются, валидация в CI (ADR-0003).
14. **Event sourcing + transactional outbox.** Auction — event sourced, интеграция между контекстами через outbox и брокер (ADR-0005).
15. **Realtime через SSE.** Цена и статус лота — `EventSource`, ставки — обычный POST (ADR-0006).
16. **Локальная разработка — kind.** Кластер с Istio, OTel, Postgres и брокером поднимается одним скриптом (ADR-0007).
17. **Деплой — Helm + ArgoCD.** GitOps с ветки `main`, руками в кластер не ходим (ADR-0007).
18. **CI экономный.** Open source, минуты ограничены. На PR только fmt, clippy и likec4 validate. Остальные шаги обозначены в workflow заглушками `if: false` (ADR-0007).
19. **Feature flags — предусмотреть.** Точка расширения в коде закладывается сразу, провайдер выбираем позже.
20. **BFF — единственная публичная точка входа.** Rust-сервис: компонует экраны, переводит команды, фан-аутит SSE. Доменных правил в нём нет (ADR-0008).
21. **Postgres + ClickHouse.** Postgres для event store и операционных проекций, ClickHouse для аналитической истории, читает брокер напрямую (ADR-0010).

Список юзкейсов и их статусы: `docs/use-cases.md`.

## Кандидаты на «что-то ещё» (не решено)

- **Брокер.** NATS JetStream, Kafka или Redpanda. Ограничение: ClickHouse должен уметь его читать напрямую (ADR-0010). Выбрать после оценки задержки для SSE и удобства в kind.
- **Идемпотентность ставок.** Idempotency key на POST. Конкуренция решена версией потока событий (ADR-0005).
- **Property-based тесты (proptest)** как мост между Rust-кодом и Lean-доказательствами: те же инварианты проверяются на случайных данных.
- **Завершение по таймеру и anti-sniping (auto-extend).** Первая команда не от пользователя: нужны часы и единственный исполнитель. Идут вместе, см. use-cases A4, A5.
- **PostHog.** Продуктовая аналитика в перспективе, не сейчас.
- **Провайдер feature flags.** OpenFeature как абстракция, провайдер позже.

## Вне скоупа

- Платежи и эскроу. Победитель определяется, деньги не двигаются.

## Открытые вопросы

- Какой тип аукциона? Предложен английский с proxy bidding, ADR-0009 в статусе Proposed.
- SDD — именно Spec-Driven Development (spec-kit / openspec) или другая расшифровка?
- Как связать Lean и Rust: ручное соответствие по спеке, или генерация/извлечение кода?
