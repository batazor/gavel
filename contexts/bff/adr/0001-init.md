# 1. Инициализация BFF на WunderGraph Cosmo Router

Date: 2026-10-22

## Status

Accepted

## Что

BFF — проект публичной API-границы Gavel. Его основа — self-hosted **WunderGraph Cosmo Router**, который предоставляет Web единый federated GraphQL interface для queries, mutations и subscriptions.

Проект также владеет отдельным Realtime subgraph. Он скрывает специфичные для Gavel replay, Redpanda fan-out и hot-lot coalescing, пока Cosmo остаётся общим GraphQL transport и execution engine.

## Зачем

Страница аукциона состоит из данных нескольких владельцев: Catalog хранит карточку лота, Auction — актуальную цену и состояние, Analytics — историю, Payments — персональный статус оплаты, Processes — долгие операции. Браузер не должен знать topology внутренних сервисов и самостоятельно компоновать их ответы.

Query planning, Federation composition, validation, persisted operations, traffic controls и telemetry не являются уникальной бизнес-логикой Gavel. Готовый router даёт их как глубокий infrastructure module с узким публичным interface, поэтому собственный gateway для этих задач не пишем.

Рассматривались Apollo GraphOS Router, WunderGraph Cosmo Router, The Guild Hive Gateway и CNCF gateways. Прямого CNCF-hosted Federation router нет: Envoy Gateway, kgateway и Higress решают ingress/L7 routing, но не строят query plan по supergraph. Cosmo выбран за Apache-2.0, compiled Go data plane, локальную composition, полностью self-hosted deployment и subscriptions с Kafka-compatible broker.

## Требования

### Публичная граница

- Cloudflare является обязательным public edge; через Cloudflare Tunnel он направляет `/graphql` в Istio Ingress, а тот — только в Cosmo Router. Внутренние subgraphs наружу не доступны.
- Router получает execution config из локальной composition и не требует vendor SaaS/control plane для работы data plane.
- Catalog, Auction, Payments, Analytics и Processes владеют своими Federation schemas и resolvers; Realtime subgraph принадлежит BFF.
- Router отвечает за GraphQL validation, persisted operations, query planning, composition, transport controls и OTLP telemetry.
- Доменные правила, идемпотентность, транзакции и authoritative SpiceDB checks остаются в сервисах-владельцах.
- Cosmo-to-subgraph transport остаётся GraphQL/HTTP; внутренние owner gRPC endpoints не маршрутизируются Router и не публикуются браузеру.
- Processes предоставляет узкий subgraph adapter; Router не запускает Temporal workflows напрямую.
- Callback платёжного провайдера не входит в graph: Cloudflare/Istio маршрутизируют отдельный path непосредственно в Payments.
- Дополнительный Envoy-class gateway поверх существующего Istio не добавляется.
- Custom Go modules разрешены только для общих edge concerns, которые нельзя выразить конфигурацией; бизнес-логика в Router запрещена.

### Realtime seam

- Web подписывается через GraphQL subscription и передаёт последнюю применённую Auction stream version как `afterVersion`.
- Realtime subgraph сначала получает пропущенные публичные события из Auction, затем подключается к live-событиям Redpanda без окна потери.
- Промежуточные `PRICE_CHANGED` и `DEADLINE_CHANGED` можно coalesce; `CLOSED`, `CANCELLED` и `PAID` нельзя терять.
- После reconnect клиент повторяет subscription с checkpoint.
- Cosmo Streams с Kafka provider можно использовать после проверки с Redpanda, но transport сам по себе не считается доказательством replay или authorization semantics.

### Authorization

- Istio проверяет подпись JWT; canonical principal строится только из verified `iss + sub`, роли JWT игнорируются.
- Публичные fields доступны без identity; protected operations требуют principal.
- Owner subgraph выполняет authoritative SpiceDB check и отдельно проверяет domain eligibility.
- Edge pre-check/BulkCheck допустим как UX-оптимизация, но не заменяет owner check.
- Authz permission и relationship APIs остаются внутренними и не публикуются как GraphQL subgraph.

### Производительность и проверка

- `currentPrice` разрешается одним обращением к Auction и укладывается в P99 < 200 мс.
- Полный экран лота и `placeBid` укладываются в P99 < 500 мс.
- `placeBid` сохраняет идемпотентность и синхронный authoritative result.
- Полная история ставок отдаётся cursor pages из Analytics; миллион ставок не материализуется одним response.
- Один query компонует экран из subgraphs без N+1; ownership полей однозначен.
- Reconnect subscription восстанавливается с Auction stream version без потери terminal events.
- k6 покрывает query/mutation throughput, concurrent subscriptions, reconnect storm и hot lot.
- Redpanda compatibility проверяется при restart Router, partition reassignment и broker lag.
- Federation composition, schema delivery и rolling update работают без обязательного внешнего control plane.
- Subscription reconnect/replay проверяется через полный Cloudflare Tunnel path, включая edge disconnect и idle connection.

- Поставлять собираемый bootstrap binary и собственные multi-stage Dockerfile, Helm chart, ServiceMonitor, PrometheusRule, Grafana dashboard в `ops/`; platform chart не хранит project-specific manifests.

## Последствия

- Каждый проект владеет своей частью GraphQL schema рядом с доменной моделью и данными.
- Breaking-change policy применяется к Federation schema и зарегистрированным client operations.
- Realtime остаётся нашим узким adapter, потому что replay и coalescing — требования Gavel.
- Cosmo Router становится критической data-plane зависимостью; capacity, upgrades и failure modes входят в availability model.
- Hive Gateway остаётся запасной альтернативой, если Cosmo не пройдёт одинаковый k6/OTel профиль или self-hosted upgrade path окажется неприемлемым.
