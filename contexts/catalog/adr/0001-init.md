# 1. Инициализация Catalog

Date: 2026-10-21

## Status

Accepted

## Что

Catalog — bounded context описания и жизненного цикла лота как предмета продажи. Он владеет названием, фотографиями, категорией, продавцом, стартовыми параметрами торгов и состоянием публикации лота.

## Зачем

Карточка товара и торги меняются по разным правилам и с разным профилем нагрузки. Отделение Catalog не позволяет торговым инвариантам смешиваться с редактированием описания и оставляет Auction единственным владельцем ставок.

## Требования

- Хранить обычное состояние лота в `catalog-db`; event sourcing для Catalog не требуется.
- Записывать изменение лота и outbox-событие в одной транзакции.
- Публиковать `LotListed`, достаточный для открытия торгов в Auction.
- Не принимать решений о наличии ставок; снятие лота координируется процессом с проверкой Auction.
- Не содержать расчёт цены, лидера или дедлайна торгов.
- Поддерживать read-heavy доступ к карточкам лотов.
- Проверять `platform#create_lot` перед созданием, `lot#edit`/`withdraw` для пользовательских команд и `lot#execute_withdraw` для шага Temporal saga.
- До транзакции создания идемпотентно provision `lot:platform` и `lot:seller` по заранее выделенному id; затем сохранить лот, ZedToken и `LotListed` outbox атомарно. Orphan tuple после failed commit чистит reconciliation.
- Владеть Federation schema для `Lot`, catalog queries и mutations; Cosmo Router только композит и исполняет этот interface.
- Владеть versioned gRPC contract идемпотентной `WithdrawLot`, вызываемой Processes после отмены аукциона.
- Хранить бинарные медиаобъекты через S3-compatible interface согласно отдельному ADR; `catalog-db` хранит только управляемые metadata и связи с лотами.

- Поставлять собираемый bootstrap binary и собственные multi-stage Dockerfile, Helm chart, ServiceMonitor, PrometheusRule, Grafana dashboard в `ops/`; platform chart не хранит project-specific manifests.
- Runtime валидирует конфигурацию до открытия listener, проверяет PostgreSQL/Authz/S3 readiness, запускает HTTP GraphQL и gRPC на разных портах, супервизирует cleanup/reconciliation workers и завершает их через cancellation token.
- GraphQL principal headers преобразуются в application extension только для loopback/trusted-proxy CIDR. `WithdrawLot` получает caller исключительно из trusted SPIFFE interceptor и требует bounded `grpc-timeout`.
